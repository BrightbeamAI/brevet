B R E V E T

Change control for what
AI agents learn.

Agents can now improve themselves: new rules, new skills, new memory. Brevet makes that learning promotable, auditable, and revocable, wrapped around the agent framework you already use.

Agents propose deltas; evidence tests them; humans promote them;
the runtime only ever executes signed versions.
bre·vet
/brəˈvɛt/

n. a commission conferring rank by signed warrant: provisional, earned in the field, and revocable by the authority that granted it. That is what a promotion here gives a capability: authority granted by a named approver, recorded, conditional, and able to be taken back.

The need

Your agent learned something on Tuesday.

Maybe it stored a memory. Maybe a self-improvement loop rewrote part of its prompt. Maybe someone pasted a new rule into a config. On Wednesday it behaves differently, and mostly better. Then something goes wrong, or an auditor walks in, and someone asks three questions that today almost nobody can answer:

“What has the agent learned?”

Not the model weights. The rules, skills, memories and tool bindings the agent has picked up since you deployed it. Today that knowledge lives in an invisible pile of prompts and glue.

Brevet: capabilities.lock, the capability bill of materials, with the hash of each capability’s exact content.

“Who approved it?”

A learned behaviour changed a real decision. Which human said that change could ship? On what evidence? Today: nobody did. It just accumulated.

Brevet: every promotion is a recorded decision by a named human or mission group, with the overrides that justified it.

“How do we take it back?”

The learned rule turned out to be wrong. Delete it? From where? From which versions? And how do you show an auditor what was done?

Brevet: recall. Withdraw the capability and flag every release that shipped it, on the evidence chain.

The sense behind it

You already trust this pattern everywhere else

Brevet invents almost nothing. Each of its mechanisms is a control you already rely on, moved to the one place that has none: what your agent learns.

package-lock.json → capabilities.lock

You pin every dependency before you ship.

npm writes a lockfile so the same code installs the same way twice, and every package has a name and a version. Brevet writes the same file for learned behaviour: every capability in a release, its content hash, and the human who approved it.

clinical trials → shadow · trial · production

A promising molecule is not a medicine.

Pharma lets discovery be bold because approval is a separate act: candidates pass phased trials before anyone prescribes them. Brevet quarantines what the agent discovers the same way. A candidate earns authority through human gates, and releases climb the channels.

CVE advisory → brevet recall

When a dependency turns dangerous, you do not shrug.

The ecosystem publishes an advisory, names the affected versions, and everyone can verify the fix. Brevet does the same for something an agent learned: recall it, flag every release that shipped it, keep identical content out of later releases, and let anyone replay the record from the chain.

maintenance release → signed agent.yaml

An aircraft flies only with the release signed.

Every modification is logged, signed, and traceable to a named engineer; otherwise the plane stays in the hangar. Outside the shadow channel, a wrapped agent runs only while its manifest signature verifies, and what it knows is a recorded human decision. No valid signature, no flight.

Four controls, each boring in its home discipline. Brevet's contribution is applying them, together, to agent learning.

Where it applies

    
Built for work that has no answer key

    
A coding agent can grade itself against tests. A quality
    reviewer cannot: no oracle says whether a deviation was major. So Brevet uses
          the signal such work already produces. Every time an
      expert changes the agent’s decision, that correction becomes a labelled test
      case. Your override history becomes the eval suite.

    

      
Pharma and med-device quality
Deviation triage, batch record review,
        CAPA drafting. Learned severity rules must be approved, versioned, and recallable.
        Change control is already the law here; Brevet speaks it natively.

      
Financial operations
Alert triage, case summaries, exception
        handling. When the agent learns that a pattern is benign, that is a policy change.
        Someone must own it, and the auditor must find them.

      
Clinical and safety documentation
Narratives, coding suggestions,
        signal triage. Experts correct drafts all day. Brevet turns those corrections
        into candidates, evals, and governed improvement.

      
Industrial operations
Shift handover, maintenance triage,
        quality inspection. Tacit knowledge like “vibration during cleaning in place (CIP) means seal wear”
        becomes an explicit, conditional, revocable capability.

      
MSPs and support engineering
Ticket triage and runbook agents that
        learn each client’s quirks. The lockfile tells you exactly what each deployment
        has learned, per client, per version.

      
Any team that fears week two
Not regulated? The questions still bite
        the first time a learned behaviour misfires in production and nobody can say when
        it appeared or how to unlearn it.

    

  







  

    
Why we built it

    
The third piece of an arc

    
Brightbeam builds the governance layer for expert agents in
        regulated industry. Each piece answers one question about a working agent:
    what happened (CHAP), what its experts know (Metis), and how it changes, on
    whose approval (Brevet).

Integration

    
Three lines. Your framework stays in charge.

        
brevet.wrap() detects the common agent
    frameworks, writes a starter manifest (agent.yaml), and starts
    the evidence chain. It never modifies the wrapped object. Execution stays in your framework; Brevet keeps the manifest, evidence and releases around it.


    

    


    

      
      
    

  







  

    
Speak Brevet

    
The vocabulary, precisely

        
These terms come from Brightbeam’s research on governed agent
    adaptation. The code, the schemas and the spec use the same terms, and GLOSSARY.md
    defines each one precisely.

    

      
harness
Everything around the model that makes it an
        agent: prompts, tools, loop policy, memory bindings, safety rails. Brevet stores the
        harness as data (agent.yaml), versioned and signed.

      
difference signal (Δ = enacted ⊖ specified)
What actually
        happened (traces and overrides) compared with what the signed harness specified.
        The ⊖ is a structured comparison of matched episodes, not subtraction.
        Every candidate is mined from this difference.

              
dream cycle
The offline mining run. It examines the
        difference signal, groups recurring overrides by failure signature, and emits candidates
        and compiled eval cases. It adds only what is new, and nothing it produces carries
        authority.

      
dawn gate
The human review moment. A named human or
        mission group applies promote, hold,
        reject, or re_elicit to each
                candidate, and the evidence chain records the decision.

      
mission group
The accountable review board: a named
        panel of humans, never a single expert. It weighs evidence, resolves conflicts, decides
        promotion or rejection, signs releases, and issues recalls, as
        mission_group:right_first_time does in the demo.

      
override
An expert’s correction: the difference between the
        agent’s draft and the final actually used, plus the rationale and tags.
        Refining: same decision, better wording. Substituting: a different
        decision, a real failure label.

      
capability object
The unit of learned capability:
        content, provenance, conditions, confidence, authority, validation-state, plus a kind
        (prompt rule, skill, tool binding, eval case, ...). One lifecycle for all of them.

              
authority ladder
Evidence: quarantined, review
        only. Advisory: may inform drafts a human still checks. Controlled: may
        drive actions directly, after promotion by a mission group. Authority only increases
        through a recorded decision by a named human or mission group.

      
endogenous / exogenous
Endogenous: the system inferred
                it from its own operational history; it enters quarantined, as a hypothesis held to a
        higher evidence bar, and cannot be promoted under a machine identity. Exogenous: a human carried it in
        or confirmed it. Human judgment grounds and verifies machine inference.

      
conservative gate
The release rule:
        Δin ≥ 0 ∧ Δout ≥ 0 ∧ max > 0.
                checked on the deltas passed to the release. A change may not trade one half of the
        eval cases against the other, even if the total improves.

              
capabilities.lock
The capability bill of materials:
        every approved capability with its content hash, authority layer, approver, and evidence
        references. One file per release; the release signature covers its digest.

              
evidence chain
The append-only record:
        sha256(canonical(envelope) ‖ prev_hash). Anyone can replay
        it offline and detect an inserted or altered entry. Detecting a removed tail or a full rewrite needs a copy of the latest entry kept elsewhere.

    

    
The full set, including channels, consent scope, failure signatures,
        and validation states, lives in
    GLOSSARY.md.
    What this version leaves to the system you deploy it in is listed under
    Project status.
